Semantica — Notion 기반 온톨로지 플랫폼

Notion 지식을 자동 구조화하여 자연어 검색과
Snowflake 데이터 분석 품질 향상에 활용합니다.

시스템 개요

Semantica는 전략사업본부 Notion에 축적된 문서와 의사결정 이력을 수집·구조화하여 자연어 질문으로 검색하고, Snowflake 분석에 직접 연결하는 온톨로지 플랫폼입니다.

Notion API 벡터 DB (Qdrant) 그래프 DB (FalkorDB) Snowflake UDF MCP 서버 (Claude)
문제 의식
Notion에 축적된 운영 이력·의사결정 맥락이 수치 분석에 연결되지 않아, 데이터 이면의 이유를 파악하는 데 시간이 소요됩니다.
해결 방식
Notion 문서를 자동 수집해 벡터·그래프 DB에 구조화하고, 자연어 질문 하나로 관련 이력을 즉시 검색합니다. Snowflake SQL에서도 동일하게 활용합니다.

데이터 분석 품질 향상

Semantica는 Notion 맥락 정보를 정량 데이터 분석에 연결하여 분석 품질을 높입니다.

운영 이벤트 ↔ 지표 연결
UA 예산 조정·이벤트 집행·정책 변경 이력이 날짜·게임 기준으로 검색됩니다. 수치 이상 발생 시 해당 기간의 운영 이벤트를 즉시 조회할 수 있습니다.
의사결정 근거 자동 참조
특정 전략이 채택된 이유, 팀 간 협의 내역, 리스크로 기록된 항목을 자연어 질문으로 즉시 검색합니다.
KPI × 온톨로지 교차 분석
Snowflake SQL에서 KPI 테이블과 온톨로지 결과를 한 쿼리로 결합합니다. 수치 리포트에 문서 맥락을 자동 포함.
HTML 첨부 문서 검색 포함
Notion에 첨부된 HTML 테이블·리포트 파일도 텍스트 변환 후 인덱싱됩니다. 파일을 직접 열지 않아도 내용을 질의로 탐색 가능.
현황: 전략사업본부 기준 약 370개 페이지 수집·인덱싱 완료. 증분 동기화로 Notion 변경 사항이 자동으로 반영됩니다. 웹 운영 대시보드(port 8080)에서 수집 현황과 검색 테스트를 실시간 확인 가능.

역할 ① — Qdrant 연결 추상화

사용 모듈
semantica.vector_store.qdrant_store.QdrantStore
ingest.py가 QdrantStore(url)를 생성하면 .connect() → .create_collection() → .insert_vectors() 순서로 Notion 청크 임베딩을 Qdrant에 적재합니다. Qdrant의 REST API를 직접 호출하는 대신 semantica의 래퍼 클래스를 사용해 컬렉션 관리와 벡터 삽입을 추상화합니다.
# ingest.py 실제 사용 패턴
from semantica.vector_store.qdrant_store import QdrantStore

store = QdrantStore(url=QDRANT_URL)
store.connect()
store.create_collection("strategic_pages", dim=768)
store.insert_vectors(chunks)

역할 ② — NER/RE Fallback 엔진 (대기 상태)

사용 모듈
semantica.semantic_extract
extract_with_fallback()에서 Claude LLM(Haiku)이 트리플 추출에 실패하거나 0개를 반환할 때 발동하도록 설계됐습니다. NamedEntityRecognizer로 엔티티를, RelationExtractor로 관계를 추출한 뒤 FalkorDB에 적재합니다.
